# Google/GitHub account setup

PaperLens works with a local profile before OAuth is configured. On first use, enter a name, research area and nationality. The avatar opens Settings, where the profile and long-term memories can be updated. The clock icon opens chat history. Account data is stored by the backend, so installations must use the same backend to share account history.

Sign-in uses authorization code + PKCE and `chrome.identity.launchWebAuthFlow`. The backend exchanges the code and requests the provider's profile. Stable Google `sub` or GitHub user ID identifies the account; display names are not account identifiers. Provider access tokens remain in the callback request's memory and are not stored in the extension or database. The extension receives a short-lived, one-use completion ticket and then a fresh PaperLens session token. No OAuth provider is simulated when credentials are missing.

## Local configuration

Create OAuth applications owned by you, then add the following to the repository-root `.env`. Use the backend's actual URL consistently. The default production extension build connects to `http://localhost:8000`.

```dotenv
AUTH_PUBLIC_BASE_URL=http://localhost:8000
GOOGLE_CLIENT_ID=your-google-web-client-id
GOOGLE_CLIENT_SECRET=your-google-client-secret
GITHUB_CLIENT_ID=your-github-oauth-client-id
GITHUB_CLIENT_SECRET=your-github-oauth-client-secret
```

Do not put secrets in the manifest, frontend, repository or chat. Each provider can be configured independently; its button is enabled only when its client ID and secret are present.

### Google

1. In [Google Cloud Console](https://console.cloud.google.com/), select your project and configure the OAuth consent screen / Google Auth Platform branding and audience. If the application is in testing, add the Google accounts that will test it.
2. Create an OAuth client of type **Web application**.
3. Register this exact authorized redirect URI:

   ```text
   http://localhost:8000/api/v1/auth/google/callback
   ```

4. Copy the client ID and secret into the backend `.env`. PaperLens requests `openid profile` and reads the account name from the authenticated user-info endpoint.

See [Google's web-server OAuth documentation](https://developers.google.com/identity/protocols/oauth2/web-server).

### GitHub

1. Open [GitHub Developer settings → OAuth Apps](https://github.com/settings/developers) and register a new OAuth App.
2. Use the backend URL as its homepage for local testing, and register this authorization callback URL:

   ```text
   http://localhost:8000/api/v1/auth/github/callback
   ```

3. Copy the client ID and generate/copy a client secret into `.env`. PaperLens requests `read:user`, reads the authenticated profile, and uses the name with login as a fallback. It does not request repository access.

See [GitHub's authorization-code/PKCE documentation](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps).

### Start and verify

Restart the backend from the repository root after editing `.env`:

```bash
python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 --reload
```

Build the extension if needed:

```bash
npm --prefix extension ci
npm --prefix extension run build
```

In `chrome://extensions`, Reload PaperLens, then reload the paper tab. The new `identity` permission may require acknowledgement. In Settings, click **Continue with Google** or **Continue with GitHub** and complete the provider's login. The avatar tooltip and Account section show the provider's account name.

The provider redirects to the backend callback above. The backend then returns to `https://<extension-id>.chromiumapp.org/oauth`, which is generated by [Chrome's Identity API](https://developer.chrome.com/docs/extensions/reference/api/identity). Register the **backend callback** with the provider; the extension redirect is the final browser handoff. Rebuilding an unpacked extension therefore does not require putting its ID into the OAuth client configuration.

Existing guest chats, profiles and memories are claimed when signing into an existing account; matching paper versions are coalesced without resetting token usage. Switching between two already authenticated accounts keeps their data separate. Sign out creates a separate local session and revokes that installation's current token; it does not erase account history or sign out other installations.

## Hosted backend

Set `AUTH_PUBLIC_BASE_URL` to the backend's public **HTTPS** URL, register the corresponding callback URI with each provider, and build the extension with its `BACKEND_URL`. Only localhost development callbacks allow HTTP. Keep the same persistent backend database for account continuity. Use `app.environment: production` for a shared service so caller-selected development identities are disabled.

## Verification boundary

OAuth's state/provider binding, PKCE parameters, one-use tickets, session rotation, second-installation identity lookup, sign-out and guest-history merge are tested with mocked provider HTTP responses. Real Google/GitHub login has not been tested because client credentials have not been configured. See the account and memory verification (local only).
